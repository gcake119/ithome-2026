# 2026 iThome 鐵人賽｜30 天系列章節結構與文章網站交接

> 本文件依 30 篇最新定稿重新整理，作為 `gcake119/ithome-2026` 首頁、系列導覽、sidebar 與文章章節 metadata 的正式依據。若與早期企劃 Part 分法不同，以本文件為準。文章正文與標題仍以各 Day Markdown 為準。

## 系列名稱

**AI 都會寫程式了，我還要學什麼？——從「做得出來」到學會開發的 30 天**

整個系列追問：當 AI 讓實作能力跑在理解前面，一個仍在學習中的開發者，如何從真實產品與委託專案裡，逐漸知道自己還需要理解哪些產品問題、工程問題，以及 Coding 本身需要理解到什麼程度。

系列閱讀原則：**先有問題，後來才有語言。**

## 正式五章

### 第一章｜實作跑在理解前面

- Day 1｜做得出來，卻完全改不動
- Day 2｜當實作跑得比理解更快

短介：AI 已經讓我可以在程式基礎仍有限時開始做真正的產品。當實作跑得比理解更快，我也開始用一種很不一樣的順序學習開發：先撞上問題，後來才知道它叫什麼。

### 第二章｜第一個產品：從做功能，到開始理解工作

- Day 3～12

短介：第一個預約管理產品裡，我原本只是想把功能一個一個做出來。一路做下去，我才逐漸開始看見人的工作、沒有說出口的條件、使用方式，以及問題本身應該怎麼被理解。

主要推進：需求從觀察與許願長出來 → LINE 影響產品形式 → 借用成熟工具 → 分辨固定工作與人的判斷 → 看見隱含條件 → AI 反問暴露理解缺口 → 系統流程與使用者流程分開 → 功能完成與產品完成分開 → 重新檢查問題框架 → Day 12 以「翻譯」替第一個產品留下的能力命名。

### 第三章｜第二個專案：理解工作的能力開始變成工程判斷

- Day 13～20

短介：進入完全陌生的委託案後，第一個產品留下的思考方式開始自然出現。以前要撞牆才想到的問題，有些開始能在實作以前被提出，並逐漸延伸成系統責任、邊界與工程判斷。

主要推進：現場觀察與流程圖 → 從工作流程看系統責任 → 今日工作台與 actionability → 從工作終點反推功能 → 拆系統責任 → multi-repo 與跨 repo 脈絡 → 決策紀錄 → 系統必須保證的條件。

公開描述合作專案時統一使用：**合作單位委託的內部行政流程進度管理工具**。不要公開真實合作單位、特定案件業務、個資、不必要的內部流程或部署資訊。

### 第四章｜AI 寫大量程式後，我怎麼理解、判斷與相信實作？

- Day 21～27

短介：當 Coding Agent 已經可以完成大量實作，我開始需要重新釐清自己到底理解了什麼，以及在不逐行閱讀程式碼的情況下，要靠哪些證據建立對實作的信任。

主要推進：透過規格/design理解系統 → 概念變成自己的判斷 → system-level 與 code-level understanding 分開 → SDD／TDD／AI review／人工 UI 驗收的多層證據 → 測試約束已知期待 → review 檢查實作方式 → 保留完整 QA 仍是能力缺口。

### 第五章｜回到最開始的問題：我現在知道自己還在學什麼

- Day 28～30

短介：30 天最後重新回到系列起點：做產品前要看懂什麼、工作進入系統後有哪些工程問題不能不問，以及 AI 已經會寫程式之後，Coding 本身到底還需要理解到多深。

收束順序：Day 28 產品／需求 → Day 29 工程 → Day 30 Coding。Day 30 保留「程式實作究竟需要理解到多深」為未解問題，不宣稱 AI 時代不需要 Coding，也不設定普遍適用的最低門檻。

## 網站實作規則

1. 正式 Day 順序固定為 Day 1～30，不因章節重整而重新排序。
2. 正式網站分組只使用以上五章，不再使用舊的產品篇／工程篇／可靠性篇等分類。
3. 章節資訊屬於 metadata；不要為增加章節而修改文章正文。
4. 現行 repo 的正式文章 collection 是 `src/content/ironman/day-NN.md`，由 `src/content.config.ts` 與 `scripts/ithome/prepare.mjs` 共同使用；不要另外建立第二套 `src/content/posts/` 文章來源。
5. 對應 section id：Day 1–2=`chapter-1`；Day 3–12=`chapter-2`；Day 13–20=`chapter-3`；Day 21–27=`chapter-4`；Day 28–30=`chapter-5`。
6. 首頁、sidebar、單篇章節標示應由 `ithome.config.json` 的 `learningMap.sections` 與各文 frontmatter `section` 動態產生。
7. 固定文章網址保持 `/day/01/`～`/day/30/`。
